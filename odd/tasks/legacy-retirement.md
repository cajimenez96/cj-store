# Legacy product fields retirement
Objective: retire the legacy product model (gender, typeId, sizesStock, displayedSizes, legacyVariants, FootwearType, GenderSize) in favor of Categories, Attributes and variants.
Branch: main, working tree only. No commits until the user asks (they review before committing). Delivery strategy: ask-on-risk.
Test runner: none in the project. Checks: `tsc --noEmit` (ignore stale `.next/types`), `eslint` vs HEAD, node assertions on pure helpers, live `curl` on the dev server (port 3000, user-owned, do not restart).

## Specs
- S1: "avancemos de manera lineal" (follow the agreed plan order, one step after another).
- S2: "De momento vendo perfumes, pero podriamos vender calzados en algun momento" (keep the Attribute-based variant sizes capability alive; only the legacy size machinery goes).
- S3: "puedes editar. te recuerdo que es una base de datos de desarrollo, no tenemos produccion aun" (dev DB at localhost:27017/cj-store may be edited; no production data to preserve).
- S4 (assumption): top-level `retailPrice`, `wholesalePrice`, `stock` and `price` on Product stay, because the product form still sends them and the storefront sorts by `retailPrice`.
- S5 (observed DB, 2026-10-13): 1 product (variants only), 0 orders, 0 footweartypes, 4 gendersizes, attributes `volumen` and `talle`; no `genero` attribute.
